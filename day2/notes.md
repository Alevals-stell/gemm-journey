Q1（基础概念）：cache line 是什么？CPU 为什么不一个字节一个字节地从内存读数据？
A: cache line是一个由状态位、标签位和实际数据组成的cpu缓存中的一部分，它的设计目的是为了让cpu从内存中尽可能快的读取数据，因为如果每一个字节都要从内存中读取数据那么cpu大部分时间都处于idle状态等待内存数据而不是处于数学运算中.
Q2（计算题）：你的 M2 缓存行是 128 字节，一个 float 是 4 字节。一条 cache line 能装几个 float？ 32
Q3（分析）：ikj 内层循环沿着 B 的一行走，顺序读 32 个 float，大约会发生几次缓存缺失、几次命中？第一次缺失，其余31次命中.
Q4（分析）：ijk 内层循环沿着 B 的一列走，每次跳 N 个 float。为什么说每次读取都"浪费"了大部分搬来的数据？因为实际参与矩阵运算的只有每行的一个数，其他数在内层循环中用不到
Q5（预测）：如果我把 B 改成列优先存储（同一列的元素在内存里连续），ijk 和 ikj 哪个会更快？为什么？ijk更快，因为最内层是沿着列来读的，此时列在内存中是连续的，cpu的内层循环几乎每一个列中的数都能参与到矩阵运算中.
Q6（联想）：这个概念和 GPU 上的"访存合并"有什么相似之处？不确定也可以猜，说说你的想法."访存合并"（coalescing）不是读和写合并，而是同一个 warp 里的 32 个线程各自发出的访存请求，被硬件合并成少数几次内存事务。
条件是：这 32 个线程访问的是相邻的连续地址。比如线程 0 读第 0 个 float，线程 1 读第 1 个，……线程 31 读第 31 个，正好是连续的 128 字节，GPU 一次事务就搬完。如果它们各自访问跳跃很远的地址，就要发起很多次事务，性能暴跌。
